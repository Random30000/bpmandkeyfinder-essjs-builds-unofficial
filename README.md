# Essentia.js WASM builds (unofficial)

This repository provides reproducible WebAssembly builds of
[Essentia.js](https://github.com/MTG/essentia.js), the JavaScript bindings for
the [Essentia](https://essentia.upf.edu/) audio analysis library. The project is
focused on BPM and musical key extraction workflows (e.g. `RhythmExtractor2013`
and `KeyExtractor`) while keeping the upstream code unchanged and documenting
every build input for auditability.

## Repository layout

```
├── dist/                # Build outputs (full & min variants)
├── examples/            # Browser and Node usage samples
├── scripts/             # Fetching upstream, local setup, and build orchestration
├── tools/               # Size reports, hashing, reproducibility helpers
├── tests/               # Vitest smoke tests running against built artifacts
├── vendor/              # Upstream Essentia.js checkout (generated by scripts)
├── Dockerfile           # Reproducible emscripten/emsdk based environment
├── build-info.json      # Auto-generated metadata for the last fetch/build
├── NOTICE               # Upstream acknowledgements and licensing
└── README.md            # This document
```

The `dist/` directory is intentionally empty in the repository. Artifacts are
produced by CI or by running the provided build scripts.

## Prerequisites

You can work either inside Docker or on your local machine.

### Local workstation requirements

* [emsdk](https://emscripten.org/docs/getting_started/downloads.html) (Emscripten)
  activated in your shell (`source ./emsdk_env.sh`).
* `git`, `cmake`, `make`, `python3`, `node`, and `npm`.
* Python environment with the upstream Essentia Python bindings available. The
  upstream `configure_bindings.py` script will import `essentia.standard`.

Run the helper script to verify your toolchain:

```bash
./scripts/setup-local.sh
```

### Docker workflow

A ready-to-use build image is provided. It extends
`emscripten/emsdk:3.1.46` with the additional build prerequisites.

```bash
# Build the container image
docker build -t essentia-wasm-builds .

# Run an interactive shell inside the image
docker run --rm -it -v "$PWD:/work" essentia-wasm-builds
```

Inside the container, the repository will be mounted at `/work`.

## Quick start

Run the smoke tests from a clean checkout:

```bash
npm ci
npm test
```

`npm test` invokes `./scripts/bootstrap.sh`, which fetches the upstream
Essentia.js repository at `${ESSENTIA_JS_REF:-v22.08}` and builds the minimal
bundle automatically when `dist/` is empty. Set `ESSENTIA_JS_REF` to pin a
different upstream tag or commit.

## Fetching the upstream sources

Clone the upstream Essentia.js repository (or refresh it to a specific commit)
using the helper script. The resolved commit, timestamp, and toolchain info are
saved into `build-info.json`.

```bash
./scripts/fetch-upstream.sh --ref v0.1.3
```

Change the `--ref` argument to any tag or commit SHA if you need a different
upstream snapshot.

## Building the WASM bundles

Two build targets are provided:

* `full` – upstream feature set (minus algorithms excluded by default).
* `min` – curated allow-list tuned for BPM and key detection workloads. The
  allow-list lives in `configs/min/included_algos.md` and can be adjusted as the
  project evolves.

Activate your emsdk environment (`emcc` must be on `$PATH`) and run:

```bash
# Full Essentia.js bundle
./scripts/build.sh full

# Minimal bundle focused on BPM/Key pipelines
./scripts/build.sh min
```

Artifacts are written to `dist/`. The most recent build target is copied to the
directory root, and variant-specific snapshots are stored under
`dist/<target>/`:

```
dist/
├── essentia-wasm.module.js
├── essentia-wasm.web.js
├── essentia-wasm.web.wasm
├── essentia.js-core.es.js
├── essentia.js-core.js
├── full/
│   ├── essentia-wasm.module.js
│   ├── essentia-wasm.web.js
│   ├── essentia-wasm.web.wasm
│   ├── essentia.js-core.es.js
│   └── essentia.js-core.js
└── min/
    ├── essentia-wasm.module.js
    ├── essentia-wasm.web.js
    ├── essentia-wasm.web.wasm
    ├── essentia.js-core.es.js
    └── essentia.js-core.js
```

During each build the repository-level SHA-256 manifest (`dist/SHA256SUMS.txt`)
is regenerated.

### Build tips

* Set the `PYTHON` environment variable if your Python executable is not named
  `python3`.
* The `min` variant relies on `configs/min/included_algos.md`. Adjust the list to
  tune the bindings without touching upstream sources.
* `node tools/size-report.js` prints plain/ gzip/ brotli sizes for every file in
  `dist/`.
* `node tools/hash.js` can be pointed at an arbitrary directory if you want to
  hash a specific subset (defaults to `dist/`).
* `node tools/compare-hash.js <dir-a> <dir-b>` compares two SHA256SUMS manifests
  for reproducibility checks.

## Examples

The examples assume that `dist/` contains the freshly built artifacts. Running
`npm test` (or `./scripts/bootstrap.sh`) will fetch the upstream repository and
produce the minimal bundle automatically when the files are missing.

### Browser

```bash
npm run example:browser
```

Open <http://localhost:4173/examples/browser/> in a browser. The console output
shows BPM, tempo confidence, and the detected key for a synthetic clip generated
at runtime (no audio assets are bundled in the repository).

Minimal browser usage:

```html
<script src="/dist/essentia-wasm.web.js"></script>
<script type="module">
  import Essentia from '/dist/essentia.js-core.es.js';

  const wasm = await EssentiaWASM({
    locateFile: (file) => `/dist/${file}`,
  });
  const essentia = new Essentia(wasm);
  // Feed Float32Array samples into Essentia APIs...
</script>
```

### Node.js

```bash
npm run example:node
```

The script instantiates the WASM module in Node, generates a deterministic
impulse/sine blend, and prints BPM/key metrics without relying on external
fixtures.

Minimal Node usage:

```js
import path from 'node:path';

const wasmModuleImport = await import('./dist/essentia-wasm.module.js');
const moduleFactory = wasmModuleImport.default ?? wasmModuleImport.EssentiaWASM;
const wasmModule = await moduleFactory({
  locateFile: (file) => path.resolve('dist', file),
});
const webBundle = await import('./dist/essentia-wasm.web.js');
const Essentia = webBundle.Essentia ?? webBundle.default;
const essentia = new Essentia(wasmModule);
// Feed Float32Array samples into Essentia APIs...
```

## Testing

Vitest powers the smoke tests. The `pretest` hook runs `./scripts/bootstrap.sh`,
which clones the upstream repository (default `${ESSENTIA_JS_REF:-v22.08}`) and
builds the minimal bundle automatically when `dist/` is empty. Run:

```bash
npm test
```

The test suite loads the built bundle, synthesizes deterministic test signals
(an impulse train for tempo and a sine wave for spectral analysis), and asserts
that the BPM estimate sits between 110–130 while basic DSP primitives produce
non-empty output.

## Continuous integration

Two GitHub Actions workflows live in `.github/workflows/`:

* **build-test** (`build.yml`) – runs on pushes and pull requests. It checks out
  the code, writes a default upstream ref (`v22.08`) when
  `ESSENTIA_JS_REF` is unset, bootstraps the minimal bundle via
  `scripts/bootstrap.sh`, installs npm dependencies, runs the Vitest smoke test,
  builds the `full` bundle, and uploads the resulting artifacts together with
  `SHA256SUMS.txt` and `build-info.json`.
* **release** (`release.yml`) – runs for `v*` tags. It performs the same
  bootstrap/test flow, rebuilds the `full` bundle, and publishes a GitHub
  Release attaching the dist files and metadata.

### 发布

```bash
git pull
git tag v0.1.0
git push origin v0.1.0
```

打 tag 会触发 Release 工作流：抓取上游、构建（min + full）、运行测试、生成体积与哈希报告，并把所有产物附在 GitHub Release 上。

## Release artifacts & reproducibility

Each release attaches the built `dist/` files, `SHA256SUMS.txt`, and
`build-info.json`. Verify downloads with:

```bash
shasum -a 256 -c dist/SHA256SUMS.txt
```

The `tools/compare-hash.js` helper compares manifests from two builds to ensure
bit-for-bit reproducibility when using the same toolchain.

## Known limitations

* Building Essentia.js still requires the full upstream toolchain (including the
  Python Essentia bindings). This repository only automates the orchestration.
* The curated `min` allow-list is tailored for BPM and key detection. Adjust it
  if your workload depends on additional Essentia algorithms.
* WebAssembly memory growth is enabled (`-s ALLOW_MEMORY_GROWTH=1`). In memory
  constrained environments you may need to pre-size `TOTAL_MEMORY` manually.
